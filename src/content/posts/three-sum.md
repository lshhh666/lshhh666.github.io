找出数组中所有和为 0 的三元组，三个下标互不相同，答案不能包含重复。有一个前置条件题目没说，要自己看出来：先排序。

所有配对都试一遍是 O(n³)，超时。降维的钥匙藏在题目的结构里：固定第一个数 nums[i]，剩下的问题变成"在有序数组里找两个数，和等于 -nums[i]"。这正是盛最多水那篇的对撞双指针：和大了右指针往回，小了左指针往前。外层一圈 O(n)，内层对撞 O(n)，总复杂度 O(n²)。

## 第一版：断了右腿的对撞

```java
while (left < right) {
    if (命中) { 记录 }
    left++;      // 每轮只有左腿在动
}
right--;         // 右腿在循环外，只退一格
```

我的第一版 while 里只有 left++，right-- 写在了循环外面。右指针几乎不动，对撞退化成左指针的单程扫描，能找到的只有恰好包含末尾元素的组合。

## 去重：两个方向的漏

这题真正的 boss 是去重，重复的三元组从两个方向漏进来。

内层：命中一对之后 left、right 各走一步，正好踩在同一个值的下一份副本上。拿 [-2, 0, 0, 2, 2] 手推：第一次命中 (0, 2)，各走一步之后指针的落点还是 0 和 2，同一对被原样再记一次。修法是记录完先滑过所有相等的值，再各走一步：

```java
ans.add(Arrays.asList(nums[i], nums[left], nums[right]));
while (left < right && nums[left] == nums[left + 1]) left++;
while (left < right && nums[right] == nums[right - 1]) right--;
left++;
right--;
```

外层：轮到 i 时如果 nums[i] 和上一个值相等，以它开头的所有组合上一轮已经找完，直接跳过。这里我连踩两脚。第一版拿 nums[i] 和 nums[left]、nums[right] 比，比较对象就找错了，该对齐的是前一个 i。改成 nums[i] == nums[i - 1] 之后，我又把跳过写成了 i++，可 for 自己还会再 i++ 一次，一次跳两格，中间没被看过的新值直接蒸发。喂一组 [-1, -1, 0, 0, 0] 就现形：正确答案 [[0, 0, 0]]，我的代码返回空。正确的写法是一个词：

```java
if (i > 0 && nums[i] == nums[i - 1]) continue;
```

continue 是"本轮到此为止，让 for 自己挪一步"，精确跳过当前这个重复值，一步不多。

## 一组骗过我的用例

修去重的中间有一版，[0, 0, 0] 这个用例在我的代码上是通过的。实际上那一版的手动 i++ 把 i 跳到了 1，left 和 right 却还是按 i = 0 算的，循环里记录的三元组是 [nums[1], nums[1], nums[2]]，前两个下标是同一个元素。三个值恰好都是 0，输出看起来毫无破绽。直到换成 [-1, -1, 0, 0, 0]，它才返回空、当场现形。

## 复杂度

排序 O(n log n)，外层 O(n) 套内层 O(n)，总体 O(n²)，空间 O(1)。
