每根垂线的高度存在数组里，任选两根围一个容器，装多少水由短板和宽度决定：面积 = min(h[i], h[j]) × (j − i)，找最大面积。

所有配对都试一遍，O(n²)，数据一大就超时。想快，得先搞清楚哪些配对根本不用试。

## 从最宽开始，每一步只动短板

左右两端是宽度最大的起点。指针往中间收，宽度一直在变小，面积想变大，高度就得补回来。那每一步动哪根板子？

把长板往里挪：宽度变小，高度还被短板卡死，面积只会更小，白挪。值得动的只有短板。挪走它，宽度丢了，但万一里面藏着更高的板子，还有救。

## 为什么敢扔

做完我发现，这题代码是最简单的部分，麻烦的是回答一个追问：扔掉的配对里万一藏着最优解呢？

假设当前 `height[left] ≤ height[right]`，左边是短板。所有"保留 left、右边换成中间某根"的配对，宽度比现在小，高度又被 `height[left]` 卡死，面积不可能超过刚算的这一步。也就是说，left 参与的所有有希望的配对，在这一步已经全部试完了。扔掉它，没有浪费任何候选。

每一步丢掉的配对，都输给已经算过的那一个。这就是对撞双指针敢跳过暴力解大部分配对的原因。代码反而很短：

```java
class Solution {
    public int maxArea(int[] height) {
        int max = 0, left = 0, right = height.length - 1;
        while (left < right) {
            max = Math.max(max, Math.min(height[left], height[right]) * (right - left));
            if (height[left] < height[right]) {
                left++;
            } else {
                right--;
            }
        }
    }
}
```

一次遍历，O(n) 时间、O(1) 空间。
