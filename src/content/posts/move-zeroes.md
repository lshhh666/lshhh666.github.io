Hot 100 双指针专题的第一题。把数组里所有的 0 挪到末尾，非零元素保持相对顺序，要求原地操作：`[0,1,0,3,12]` 变成 `[1,3,12,0,0]`。

题干里"原地"和"相对顺序"这两个词，基本把解法圈出来了：不能开新数组抄一遍，只能在原数组里往前"压实"。我的第一直觉是人眼做事的方式，扫一遍，看见非零的就往前挪。翻译成代码就是两个下标，`i` 从头到尾扫描，`last` 记录"下一个非零数该放的位置"。`last` 左边永远是整理好的区域，快慢指针的读写分离，一个管读，一个管写。

## 第一版：思路全对，雷是自己埋的

```java
class Solution {
    public void moveZeroes(int[] nums) {
        int last=0
        for(int i=0;i<nums.length;i++){
            if(nums[i]!=0){
                nums[last]=nums[i];
                nums[i]=0;
                last++;
            }
        }
    }
}
```

连分号都忘了（提交前发现了），但真正的雷在 `nums[i]=0` 这一行。当时的想法很顺：把非零数赋值到 `last` 的位置，顺手把 `i` 那一格清成 0。跑示例 `[0,1,0,3,12]`，结果完全正确。

换 `[1,0]` 手动走一遍：

| i | 动作 | 数组变成 | last |
|---|---|---|---|
| 0 | nums[0]≠0，赋值 nums[last]=nums[0]，再把 nums[0] 清零 | [0,0] | 1 |
| 1 | nums[1]=0，跳过 | [0,0] | 1 |

正确答案是 `[1,0]`，我的输出是 `[0,0]`，1 被我自己清掉了。

问题出在两个指针重合的时候。还没遇到 0 之前，`i` 和 `last` 指向同一格，"赋值过去再把自己置零"就变成了自己清自己。示例 `[0,1,0,3,12]` 开头恰好是 0，两个指针从一开始就错开了，所以拿示例调试永远发现不了这个 bug。它只在数组开头没有 0 的用例里出现。

## 修正：把赋值换成交换

```java
class Solution {
    public void moveZeroes(int[] nums) {
        int last = 0;
        for (int i = 0; i < nums.length; i++) {
            if (nums[i] != 0) {
                int t = nums[last];
                nums[last] = nums[i];
                nums[i] = t;
                last++;
            }
        }
    }
}
```

交换法没这个问题。`i == last` 时自己和自己交换，等于什么都没做；两个指针错开时，`last` 位置上原来躺着的 0 会被换到 `i` 的位置，非零数到位，0 也顺路归位，不需要事后补零。

时间 O(n)，每个元素至多被交换一次；空间 O(1)，只有 i、last、t 三个变量。
